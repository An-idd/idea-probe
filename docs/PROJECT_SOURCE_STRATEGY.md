# 围绕个人已有想法的数据源策略

日期：2026-09-14。用户确认的方向：优先验证自己的已有想法。

研究应围绕“谁遇到了这个问题、现有方案为何不够、最小实现是什么、什么证据会推翻这个想法”展开。
不以每日论文、新产品数量或热榜排名作为需求证明。这里的高低优先级是证据用途判断，不是新增的数值权重算法。

## 本次已实施

| 处理 | 来源 | 原因 |
|---|---|---|
| 删除 | arXiv、HF Daily Papers、EmergentMind、PaperDigest、OpenReview | 批量论文发现与验证个人产品需求距离较远；研究特定技术时再按需查原论文 |
| 删除 | 泛 RSS、研究博客/会议讨论、Jina 中文媒体 | 二手报道与泛资讯噪声大，不能替代用户需求证据；还存在链接错误和访问失败 |
| 默认保留 | Hacker News | 定向检索相关用户经历、求助、替代方案及评论 |
| 保留、默认关闭 | Reddit | 用户经历仍有价值，低可访问性不等于低证据价值；当前匿名采集实测 403 |
| 保留、默认关闭 | GitHub Trending | 可发现工具，但与指定想法相关性弱；仓库简介不能证明用户需求 |
| 保留 | 现有竞品页面抓取 | 核验功能覆盖与替代方案；目前最多抓取配置允许的页面数 |

采集注册表从 11 类减到 3 类。移除 8 个模块、仅用于它们的配置常量和 `requirements-sources.txt`。
不卸载用户虚拟环境中的包。运行依赖仍为 `httpx`、`beautifulsoup4`。

默认搜索只使用 `topic` 和显式 `queries`；删除 developer tools/workaround/alternative/Ask HN 等泛化默认词。
提供的附加查询仍是独立检索，应写成与想法相关的具体问题。缺少主题和查询时，采集前报错。
显式启用 Reddit/GitHub 的本地配置仍会生效；旧配置中关闭的 academic/media 字段兼容读取，启用则明确报错。

原始需求规格和历史评估保留；配置指纹已变化，使用新运行 ID，旧研究产物不删除。

## 建议新增，按顺序开发（尚未实现）

### 1. 自己的想法说明与种子证据

增加本地 `Idea.md` 输入和少量用户提供的公开证据 URL。建议字段：

- 想法、目标用户、触发问题的具体场景；
- 当前解决方式、预期改进、已有替代品；
- 技术/时间/预算边界；
- 已知证据，以及什么结果会让自己放弃。

想法说明是待验证假设，不能计为外部需求证据。个人观察单独标注来源，不能虚构独立用户。
先检索和验证原想法，证据不足输出 HOLD；建议的替代方向另列，避免自动换题后声称原想法成立。
这需要修改输入和后续分析阶段：当前 `--topic` 仍然是在主题下发现候选，并非完整的已有想法验证模式。

### 2. GitHub 定向 Issues，再加 Discussions

先按种子仓库和相关仓库检索具体问题、功能请求、绕行方案以及维护者解释。
GitHub 官方支持按仓库、类型等条件查找 Issues，并提供正文、评论数和关联仓库等字段：
[Issue 搜索](https://docs.github.com/en/issues/tracking-your-work-with-issues/using-issues/filtering-and-searching-issues-and-pull-requests)、
[Issues REST API](https://docs.github.com/en/rest/issues/issues)。

先做 Issues 与有界评论抓取；Discussions 另行核验接口与认证要求，不把它当成同一个现成接口。
看 open 和 closed、已有修复/版本，区分可由小补丁解决的问题与值得独立产品解决的问题。
机器人、同一作者/讨论串、重复转载不能重复计为独立需求。

### 3. 按想法检索相关仓库、竞品文档、定价与变更记录

仓库用于发现替代方案、许可证和维护状态；文档、定价、changelog 用于验证功能、限制和成本。
复用现有受限页面抓取器，补充用户种子链接和定向发现入口，避免搭建全网爬虫。
官方营销声明仅能证明产品宣称了什么，不能单独证明用户需求或使用效果。

### 4. Stack Overflow / Stack Exchange，按需增加

适合开发工具想法的具体问题、失败场景和绕行方案。官方有[高级搜索接口](https://api.stackexchange.com/docs/advanced-search)。
优先检查时间、依赖版本与已采纳答案；已经被当前工具解决的问题不应被当成未满足需求。
仅在 HN + GitHub + 种子证据覆盖不足时实施。

暂不增加 Product Hunt 热榜、泛新闻、X 全站抓取、大批评论聚合站。后续若目标用户改变，再按问题选择垂直社区。

## 证据优先级与验收

第一优先：相关真实用户的具体经历、可复现限制、当前 workaround。
第二优先：官方竞品事实，用于反证差异化与核算成本。
背景材料：论文、博客、热榜，仅在解释某个实现问题时补充。

优先相关性、具体程度、独立性、时效和可追溯性，不给某个平台的所有内容统一加分。
HN 也可能是宣传或过时讨论，多个帖子不自动等于市场需求；目前默认仅一个平台，应在报告中明确覆盖有限。

新增采集器验收必须覆盖真实访问与解析、空结果/失败区分、原文链接、日期、主题相关性、重复证据和请求预算。
本次精简不降低 GO 的证据门槛，不把源减少后的证据不足用分数补齐。
